## كيف أعدّل ملفات الواجهة (مهم)

أين تقع الشيفرة؟

| الصفحة | HTML + CSS | شيفرة JavaScript |
|---|---|---|
| الرئيسية (`/`) | `src/legacy/app.html` (الهيكل فقط) | **الأنماط:** `public/legacy/app/css/*.css` · **الشعار:** `public/legacy/app/img/` · **السكربتات:** `public/legacy/app/NN-*.js` — **الرئيسي مقسّم إلى 8 ملفات:** الدوال في `03-main-01…07-functions.js` وكل ما يُنفَّذ عند التحميل في `03-main-08-init.js`؛ الترجمة `02-i18n.js`، العدّادات `18-home-welcome.js`، إدارة الطلاب `17-students-admin.js`، المناهج `11-mda-layer.js` و`08-master-curriculum-enhancements.js` … |
| الجداول (`emplois`) | `src/legacy/emplois.html` | **داخل الملف نفسه** (لم تتغير) |
| المجتمع (`community`) | `src/legacy/community.html` | **داخل الملف نفسه** (لم تتغير) |
| النتائج (`resultats`) | `src/legacy/resultats.html` | **داخل الملف نفسه** (لم تتغير) |
| بوابة الطالب / الرفع | — | `public/unem-gate.js` و`public/unem-upload.js` |

الخطوات بعد أي تعديل:

1. عدّل الملف المناسب من الجدول أعلاه (للجافاسكربت في `app.html` ابحث عن اسم الدالة داخل `public/legacy/app/`).
   - **قاعدة تقسيم الملف الرئيسي:** *الدوال الجديدة* تُوضع في أي ملف `03-main-0N-functions.js`؛ أما **أي كود يُنفَّذ فور التحميل** (متغيرات علوية، `addEventListener`، استدعاءات تهيئة) فيُوضع في `03-main-08-init.js` فقط. لا تنقله إلى ملف آخر ولا تقسّم ملف `init`: المتصفح ينفّذ المهام غير المتزامنة بين ملفين متتاليين فقد تُستدعى دالة قبل تعريف متغير.
2. شغّل **أمراً واحداً**:  `node tools/check-legacy.mjs --fix`
   - يحدّث رقم `?v=` (حتى لا يعرض المتصفح نسخة قديمة مخزّنة) ويفحص صياغة **كل** السكربتات في كل الصفحات، ويطبع ✅ أو يحدد الملف المعطوب.
3. (اختياري لكن مفضّل قبل النشر) شغّل الاختبارات: `cd tests && npm test` (انظر `tests/README.md`).
4. ارفع التغييرات كلها: التي في `src/` **و`public/legacy/`** (نسيان `public/legacy/` يعني أن الموقع يبقى بالجافاسكربت القديم).

ملاحظات:
- تعديل `emplois.html` أو `community.html` أو `resultats.html` **لا يحتاج** الخطوة 2 للتحديث (لا تحمل ملفات خارجية)، لكن تشغيلها آمن ويفحص الصياغة.
- تعديل نص أو تصميم في `app.html` فقط (HTML/CSS) لا يحتاج الخطوة 2 أيضاً.
- إن غيّرت جدول/دالة في قاعدة البيانات فأضف ملف SQL جديداً في `db/` باسم يبدأ بتاريخ أحدث، ثم حدّث القائمة: `bash db/manifest.sh > db/MANIFEST.txt`.

## هيكل الواجهة (للمرجع)

- `src/legacy/app.html` صغير (~85KB بدل 1.5MB): الأنماط في `public/legacy/app/css/` والسكربتات في `public/legacy/app/` والشعاران في ملفين — كلها بنفس الترتيب الأصلي فتبقى الواجهة والمتغيرات والدوال كما كانت (تحقّقتُ بمقارنة الأنماط المحسوبة لكل عنصر ولقطات الشاشة ومصدر كل دالة عامة). الفائدة: تحميل أسرع وتخزين مؤقت في المتصفح.
- قاعدة البيانات: انظر `db/README.md`. الاختبارات: انظر `tests/README.md`.
- الدردشة تستعمل **Supabase Realtime Broadcast** للتحديث اللحظي (مفعّل افتراضياً في كل مشروع Supabase)، وتعود تلقائياً للاستطلاع كل 4 ثوانٍ إن تعذّر.
- نافذتا «ثبّت التطبيق» و«فعّل الإشعارات»: **مخفيتان افتراضياً** ولا تظهران إلا بعد أن يفعّلهما المشرف من لوحة المشرف ← إعدادات المنصة (يتطلب ملفي `db/20261027…` و`db/20261028…`).
  الحارس موجود في `app.html` نفسه (CSS + سكربت `unem-prompts-guard`) فيبقى فعّالاً حتى لو كان أحد ملفات `public/legacy/` قديماً.
- **كاشف عدم التطابق:** عند فتح المشرف لبطاقة النافذتين، إن كان أي ملف في `public/legacy/` على الخادم يختلف عمّا يتوقعه `app.html` (نُسي رفعه أو رُفعت نسخة قديمة) يظهر تحذير أحمر باسم الملف. يشمل ذلك ملفات CSS والصور.
  القاعدة الذهبية للنشر: **ارفع `src/legacy/app.html` و`public/legacy/` معاً دائماً.**

## الفحص التلقائي (GitHub Actions)

الملف `.github/workflows/ci.yml` يشغّل عند **كل رفع (push) وكل طلب دمج (pull request)** ثلاثة فحوص:

| الفحص | ماذا يفحص | الزمن |
|---|---|---|
| `legacy-check` | صياغة كل سكربتات الواجهة + أرقام `?v=` (يلتقط ملفاً منسياً أو خطأ كتابة) | ثوانٍ |
| `e2e` | اختبارات الواجهة (دخول الطالب، رفع ملف، فتح مادة، المجتمع، النافذتان، تحميل الصفحة كاملة) | دقائق |
| `database` | بناء قاعدة PostgreSQL فارغة من كل ملفات SQL مرتين + الفحوص الوظيفية | دقيقة |

- النتيجة تظهر بجانب كل رفع في GitHub بعلامة ✅ أو ❌ (تبويب **Actions** يعرض التفاصيل).
- **لمنع نشر كود فاشل فعلياً:** Settings ← Branches ← Add rule للفرع الرئيسي ← فعّل *Require a pull request* و*Require status checks* واختر `legacy-check` و`e2e` و`database`. بدون هذه القاعدة يبقى الفحص تنبيهاً فقط (يرفع ولا يمنع).
- نفس الفحوص تُشغَّل يدوياً قبل الرفع: `node tools/check-legacy.mjs --fix` ثم `cd tests && npm ci && npx playwright install chromium && npm test`.
